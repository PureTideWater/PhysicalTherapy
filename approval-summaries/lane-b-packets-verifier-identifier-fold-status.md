## Proposals for the orchestrator (none blocks this item)
- **P1, a founder ruling.** A patient whose name is, or folds to, a word narratives use fails every narrative that uses it: TO, AN, THE, MAY, WILL already did before this change (170 plain-word names in review 2's run failed old and new alike); with the fold THẾ and TÔ join them. For "to" and "the" no rephrasing works, and the code's own draft fails, so that case gets no approvable packet. ADR 0047 accepted "the person rephrases" for MAY. Options to rule on: leave it; read a whole name of two or three letters only when it is written with a capital inside a sentence; or let a second person's attestation pass a named word.
- **P2, the UX queue.** `failsNowRefusal` (apps/web/src/lib/packets/view.ts): leave "Its figures are marked under Narrative above" out when the only marks would be `identifier_in_narrative`, and say that saving the narrative again shows where.
- **P3, cost.** The whole-word reading compiles a pattern for each form on every check: about 3 s for 10,000 identifiers on a case's first check, as before this change. A prefilter on folded letters would remove it, and needs a test over every code point that case-insensitive equality implies folded equality.
- **P4, for the leaks item (Queues 22 and 26).** The gateway's drafter refuses to draft for a case whose patient's name has a part of two or three letters that is a word of the facts ("in" of HYE-IN), since #80. The verifier's floor of four letters is not given to that check by this change: what it checks is sent to a model.
- **P5, mutation.** `packages/redact/src/redact.ts` is not in a mutate set (ADR 0066, Part 4, amendment of 2026-11-11 says why); measuring it is an item of its own.
