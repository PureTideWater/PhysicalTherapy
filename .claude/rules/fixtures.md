# Fixtures (full decision: docs/adr/0059)

- Every fixture is synthetic and generated by packages/synth (`pnpm synth --all`, or `--case <id>`). Never a real
  835, export, contract or file of a vendor's, not even redacted; a vendor's format arrives as a description and
  redacted headers, and becomes registry data in packages/synth/src/formats/vendors/registry.ts.
- X12: ISA06 is SYNTHSENDER and GS02 is SYNTH in every interchange, a byte-order mark or a zip around it included.
- Tables (D14 option a): a .csv or .tsv carries SYNTHSENDER in every data row of an identifier column, after a
  header row. For a vendor fixture (fixtures/synthetic/emr/<format_id>/) that column is the registry's
  `markerColumn` (its payee or sender ID); for any other table, a column whose header has the word ID or
  identifier (Payee ID, Originator ID). No banner or comment row: row 1 is the header the ledger reads.
- Spreadsheets: an .xlsx fixture is generated, never written by hand, and every sheet with data meets the same
  rule. .xls, .xlsm, .xlsb and .ods fixtures are refused. Intake refuses a spreadsheet posting or bank export.
- A reference table whose bytes other files pin (release manifests, golden sources, the MOD-01 baseline,
  AUDIT-01's worksheet) passes only at its path with its exact sha256, listed with the reason in
  packages/synth/src/guard/pinned-tables.json. Add one only with that reason; never to let a table skip the marker.
- One implementation enforces the rule three times: `assertSyntheticFixture` (packages/synth/src/write.ts) on
  every file writeCases and the audit writer write, `.claude/hooks/fixture-guard.sh` on Claude's Write, Edit and
  MultiEdit (through packages/synth/src/guard/cli.ts), and `pnpm check:fixtures` in `pnpm test` and CI.
- A refusal names the file and the rule, never a cell's value. Do not echo a refused file's contents to work out
  why: the file may be real. Regenerate it instead.
- The founder's approval of docs/product/domain-model.md ("Approved by:") and packages/db/domain-model/approvers.json
  are written only on the founder's instruction, by the founder; `.claude/hooks/protect-approval.sh` refuses edits.
