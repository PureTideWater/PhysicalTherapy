# Starter kit notes and milestone opening prompts

Imported from the "Starter kit" tab of the planning document (as of 2026-10-14; checked against the Claude Code documentation on October 13, 2026). The configuration files themselves live where the Starter kit puts them: `CLAUDE.md`, `.claude/rules/`, `.claude/settings.json`, `.claude/hooks/`, `.claude/skills/`, `.claude/agents/` and `.github/workflows/ci.yml`. Nothing here ever holds real data.

## Notes on the configuration

- **`.claude/settings.json`.** The `Read` denies cover the places a real file would land on a laptop; real data is never on the development machine in the first place, so these are the second fence, not the first. `denyWrite` makes published releases read-only for every command; `failIfUnavailable` stops a session on a machine where the sandbox cannot run.
- **Hooks.** Make all three executable with `chmod +x`. Exit code 2 blocks a PreToolUse call and surfaces the message; on PostToolUse the edit stands and exit 2 hands Claude the errors to fix next.
- **CI.** `tools/check-releases-immutable.sh` fails the build if any file under an existing `content/releases/<n>` differs from the base branch. A second workflow, `publish-content.yml`, runs on push to main and moves `content/outgoing/<n>` into `content/releases/<n>` after verifying its manifest. The Claude review workflow is created with `/install-github-app`, not hand-written. No workflow has credentials to any environment that holds PHI.
