- **Fields per entry** (one family = one or more record types read together):
  - `family`: a closed id;
  - `recordTypes` (a subset of RULE_RECORD_TYPES, schema.ts:20-38);
  - `title` (customer words) and `sourceTitle`;
  - `sourcePage` (https URL);
  - `cadence`: annual with effective MM-DD, quarterly (CMS A to D, schema.ts `cmsQuarterOf` :67-71), three times
    yearly with effective MM-DDs, or on change;
  - `usualPublication`: days before the effective date, or a fixed MM-DD for the final rule (early November,
    combined-report.md:726);
  - `graceDays`;
  - `ends`: `window` (closed windows that run out) or `open` (open-ended records);

  - `filePattern` and `knownFiles`, for the source-page watch (§6);
  - `reviewedBy` and `reviewedOn`: a named person and a date, mirroring `verification.by/on` (schema.ts:409-416).

## 5. Design input: the pure function

- **Suggested signature:** `contentDue(calendar, sources, today): DueItem[]`. It has no clock and no input/output.
  - `today` is a UTC calendar date. The worker has `todayUtc` (exported from apps/worker/src/runtime.ts:32), and the web
    has `services.now()` (apps/web/src/lib/server/services.ts:57, defaulted at :183).
  - `sources` holds `{ inForce, prepared?, drafts? }`, each a per-type summary `{ windows, newestFrom, newestRetrieved }`.
    The web and the job fill only `inForce` (from the database). The workflow fills all three from files: the newest
    `content/releases/<n>`, every `content/outgoing/<n>`, and `content/drafts`.
- **Windowed families:**
  - `loadedThrough` = the end of the coverage run that contains `today`, or else the latest end. Under #30's R4 (no gap
    inside a type) this is the latest end. It is null when nothing is loaded.
  - Stages: `ends_in_45` when 14 < days ≤ 45, `ends_in_14` when 0 ≤ days ≤ 14, `ended` when days < 0, where days is
    integer day arithmetic on ISO dates.
  - The audit asks for 45 and 14 (combined-report.md:727). `ended` is added because January's wall (:726) must not go
    silent after day 0.
- **Open families:** `overdue` when the latest period whose expected publication plus grace ≤ today has no record with
  `effective_from` ≥ that period's start in the in-force set, and no source retrieved on or after that expected
  publication.
- **The workflow's signal** (the audit's "main signal", :727): `no_draft`. The next period's expected publication plus
  grace has passed, and no draft, prepared release or published release covers that period's first day.
- **Each DueItem carries:**
  - family, stage and dates (`endsOn`, `expectedOn`, the next period's `from` and `to`);
  - `commands`: the exact `pnpm rules:import` lines (package.json:25), with type, year, window and URL filled.
    Only the file name is a placeholder, because CMS renames files each release (README:44-45).
  - The windows are quarter-exact, as #30's R1 requires (`--effective-from <quarter start> --effective-to <quarter end>`;
    scout-pipeline.md §3 R1). So the issue's commands and the importer's new refusal agree by construction.
- **Tests:** fast-check is already a dev dependency of rules (packages/rules/package.json:23). Example properties:
  - stages never move backwards as `today` advances;
  - nothing is due when loadedThrough ≥ today + 46;
  - the commands always parse with the import CLI's options (packages/rules/src/cli/import.ts:213-217, 239-240, 275-277).
- **Money and PHI:** none. Dates and counts only, and code computes everything.
- **Shared with #7:** #7 (in this same PR) words a fee-schedule gap on Coverage as "PaidWhole has not loaded the <year>
  fee schedule" (combined-report.md:258). That wording and #59's banner should read the same `loadedThrough`, so one
  computation serves both.
