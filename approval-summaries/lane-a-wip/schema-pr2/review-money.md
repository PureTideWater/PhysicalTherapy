## Findings
1. should-fix. equivalence.md item 5 / item 2(c),(e) claim that the divergent state is "not reachable without a superuser". This is false. tp_owner (NOSUPERUSER NOBYPASSRLS, the migration role) holds UPDATE on service_line (`has_table_privilege('tp_owner','service_line','UPDATE') = t`). The only UPDATE trigger on service_line is set_updated_at (service_line_references_in_practice is tgtype 7, INSERT only). In copy 1, with triggers and FKs on, under scope {P1,P2}, `SET LOCAL ROLE tp_owner; UPDATE service_line SET practice_id = <P2> WHERE id = <line with a P1 approved 25>` was accepted, and then: tp_owner `old_after 25 | new_after 0 | installed 25`, tp_app `25 | 0`. A future migration or owner-run job that re-homes a line would change approved/posted/deposited nets, and therefore the within_line refusals. Smallest fix: amend item 5 to name tp_owner UPDATE on service_line.practice_id as the reachable divergence and state that no migration or code does it (grep), or (in a separate change outside this grant) add a BEFORE UPDATE OF practice_id guard on service_line.
2. note. A NULL line with a malformed app.practice_ids ('' or 'garbage'; '' is what a custom GUC reverts to after SET LOCAL in a pooled session) gives `old: 0 | new: ERR 22P02 malformed array literal: ""`. A non-NULL line raises 22P02 in both. This cannot happen from the trigger (it only calls with a non-NULL line inside a valid scope), and no non-test TS code calls ledger_line_net. It is still a different refusal for a tp_app-executable function, and equivalence item 2 ("no line ... 0, as before") omits it. Fix: name it in equivalence.md, or accept it explicitly.
3. should-fix (test gap). Every net test runs in a one-practice scope (withJobScope, l.164-165), and so does every trigger call. A mutant that replaces `(SELECT l.practice_id FROM service_line l WHERE l.id = line)` with `(current_setting('app.practice_ids', true)::uuid[])[1]` passes l.167-192 and still uses the index. Fix: add an `own line` assertion at l.170-172 under a two-practice scope with the other practice listed first.
4. note (test gap). No test covers a correction whose target is missing, or whose target is an adjustment with a missing target (superuser states), so a mutant that coalesces a missing target to the entry's own stage passes. My side-by-side covered these: equal.
5. should-fix (method gap). A reconcile pass writes job entries only. The correction path of ledger_entry_rules (changed statement 1) and every refusal path are not exercised by the write-equality dumps, so `IDENTICAL` there proves nothing about them. Only l.139-160 and the truth table cover them. Fix: say so in the status file. Optionally, add a pass step that adjusts and reverses one match, so that its rows enter the dump.
