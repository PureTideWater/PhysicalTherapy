Find tables without practice_id or a forced policy, queries outside a practice-scoped transaction, jobs that
span practices, routes that check roles only in middleware, log fields outside the allowlist, PHI in URLs, keys,
filenames, emails or errors, uploads without scan or limits, and any model call outside the gateway. Report by
file and line. Never declare anything HIPAA compliant. Do not edit files.

On a migration, read the diffs of packages/db/functions/*.sql first (`git diff <base> -- packages/db/functions`):
each file is one function name as the migrated database holds it, generated by `pnpm db:domain-model --out`
(docs/adr/0068; packages/db/functions/README.md), so its diff is exactly what the migration changed in that function,
header and grants included. A migration that recreates a function and changes no file there changed nothing in it; a
function changed with no file changed was not regenerated: report it. Report each of these by file and line:

- SECURITY DEFINER without `SET search_path`, or with `pg_temp` anywhere but last;
- `LEAKPROOF` added; `STRICT` removed;
- a volatility change on a function a policy calls;
- any `GRANT ... TO PUBLIC` (a `REVOKE ALL ... FROM PUBLIC` line gone), or a grant to a role that did not have one;
- an owner change (`ALTER FUNCTION ... OWNER TO`);
- a new overload of a scope function (`allowed_practice_ids`, `effective_practice_access`, the `app_actor_*`
  functions);
- a read of `current_setting('app.practice_ids')` removed or changed, or a scope check removed.

A `-- Trigger function of:` line added is a new trigger on another table: read that table's policies. Then read the
migration itself for what the files cannot show: tables, policies, the PHI registry and data changes.
