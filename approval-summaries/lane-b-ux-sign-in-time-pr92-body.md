### Decisions taken without asking, with reasons

Under the founder's standing rule of 2026-10-18 (the best option only, not weighted by build effort) and the co-founder's delegation of 2026-10-25 (take each recommended option and wording without asking, report the departures). Each is reversible by the founder.

1. **Security: the safer option each time.**
   - The server enforces the limit itself, counted from a start taken **before** the provider call, so the app can only close a step earlier than Cognito (by the length of the call), never later; it is strictly tighter than today.
   - The kept email lives in a **sealed**, HttpOnly cookie under its own seal purpose, not signed only (readable in base64), not browser storage (readable by any script), never in a URL, a log, an error or a job payload. `Path=/`, not `/sign-in`, because a delete whose path differs from the set's silently fails and the cookie would outlive the session or lock that should end it. SameSite=Lax, the house rule (`docs/product/sessions.md`).
   - It is written only after the provider accepted the password, never by `writePending` and never for the hardware-key step, whose options are issued for any address, so it cannot be minted for an address someone merely typed. An unknown address and a wrong password write the same two deletions (no new enumeration signal).
   - It ends on a session, a lock, a key required or registered, an account found disabled or removed after a proven step, and any first step that opens none; it is filled only on `step_expired` and `restarted`. The residual risk (a shared computer showing the last person's address within 18 minutes, 30 after key registration; never a password, a code, a step or a session) is accepted with reasons in ADR 0081; a shorter life fails the person it is for, a one-time read is lost on reload.
   - No test knob for time in production code: the server is tested on its injected clock, the browser on Playwright's clock, and one e2e test waits the real 3 minutes.
   - Start again is a POST from the step's own form that ends the step on the server (above); it takes no `next` or `returnTo`, so no open redirect; a new step still costs the password under the `sign_in` rate limit, and an expiry or a Start again neither adds to nor resets `failed_sign_ins`.
2. **Wording, within `.claude/rules/brand.md`, `docs/brand/BRAND.md` and CO-11, reported to the co-founder** (design 6.1; `pnpm lint:copy` passes). Each departure from the review's recommended words:

(UX-012) | "This step closes within a minute" (the warning's title; the cue reads "This step closes within a minute.") | The warning stays up for the whole minute: "in 1 minute" is false a second later, and updating it is the ticking count rejected for 2.2.2.
