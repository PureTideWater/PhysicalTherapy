# Readable database-function diffs (combined audit #111; LANES queue item 4)

Lane B, branch `co-001/db-function-diffs`, worktree `/home/user/db-function-diffs`. Design of 2026-10-25 ~23:55 UTC,
against `claude/build-platform` at the head the branch is cut from. Reserved: ADR 0068, test-matrix DBF-01 to DBF-05,
no `packages/synth` IDs.

## 1. The problem (audit #111, checked against the tree)

- A migration changes a function by copying the whole `CREATE OR REPLACE FUNCTION` into a new file. A reviewer sees
  a new 40-line block, not the one line that changed, and has to find the previous definition (any of up to five
  earlier migrations) and diff it by hand.
- `docs/product/domain-model.md` Appendix C shows each function's body only as the first 16 hex digits of its SHA-256.
  The founder approves the document by hash, so a changed body is visible there as a changed hash, never as the change.
- The functions hold the rules that never bend: the tenancy scope (`allowed_practice_ids`, `effective_practice_access`,
  `app_actor_*`), the append-only and approval guards, the ledger's triggers. 338 functions (339 rows: one overloaded
  name, `submit_prospect_request`), all `prokind = 'f'`, all owned by `tp_owner`, one with a SQL-standard body.

## 2. Confirmed at design: no migration

"What it changes: Pricing engine: no. Ledger: no. Database: no schema change." The design reads the catalog the
domain-model generator already reads, in the same READ ONLY transaction, and writes text files. It adds no migration,
edits none, changes no table, function, policy, grant or role, and leaves `docs/product/domain-model.md`'s text, and
so its SHA-256 and the founder's approval, byte for byte unchanged. Lane B may build it (LANES rule 2).

## 3. The design

### 3.1 One generated file per function name: `packages/db/functions/<name>.sql`

- **Where:** `packages/db/functions/`, beside `packages/db/migrations/`, so a schema PR's "Files changed" shows the
  migration and, right under it, the function files it changed.
- **One file per name, overloads together** (sorted by their signature in C order). A file per name keeps the path
  stable for git history (`git log -p packages/db/functions/allowed_practice_ids.sql` is the function's whole
  evolution), and a changed argument list (a DROP and CREATE in PostgreSQL) shows as a diff of that file, not as one
  file deleted and another added. Names are refused (DomainModelError, exit 2) unless they match
  `^[a-z_][a-z0-9_]*$` and are at most 63 bytes, so no name can escape the directory or collide by case.
- **Content, deterministic** (no timestamp, commit, database name, OID or collation-dependent order), for each overload:

  ```sql
  -- Generated by `pnpm db:domain-model --out` from a freshly migrated database (docs/adr/0068).
  -- Do not edit: change the function in a new migration, then regenerate. CI fails when this file differs.

  -- public.allowed_practice_ids()
  -- Body SHA-256 in docs/product/domain-model.md, Appendix C: f2ef1aad2276f6cd
  -- Defined by: 20261015140000_tenancy.sql, 20261015180000_tenancy_hardening.sql
  -- Trigger function of: (none)
  CREATE OR REPLACE FUNCTION public.allowed_practice_ids()
   RETURNS uuid[]
   LANGUAGE sql
   STABLE SECURITY DEFINER
   SET search_path TO 'pg_catalog', 'public', 'pg_temp'
  AS $function$
    SELECT coalesce(array_agg(DISTINCT practice_id ORDER BY practice_id), '{}') FROM effective_practice_access()
  $function$;
  ALTER FUNCTION public.allowed_practice_ids() OWNER TO tp_owner;
  REVOKE ALL ON FUNCTION public.allowed_practice_ids() FROM PUBLIC;
  GRANT EXECUTE ON FUNCTION public.allowed_practice_ids() TO tp_app;
  ```

  - The definition is `pg_get_functiondef(oid)`: the header (arguments with defaults, return type, language,
    volatility, SECURITY DEFINER, LEAKPROOF, strictness, parallel safety, cost, rows, every `SET`) and the body as the
    catalog holds it. That is exactly what decides behaviour, printed by PostgreSQL itself, under the generator's
    pinned search_path, IntervalStyle, DateStyle and TimeZone.
  - The privileges are the function's ACL as statements: `REVOKE ALL ... FROM PUBLIC` when PUBLIC holds no EXECUTE,
    then one `GRANT EXECUTE ... TO <role>` per grantee in C order (`WITH GRANT OPTION` where it is grantable), the
    owner as `ALTER FUNCTION ... OWNER TO`. A grant added to a SECURITY DEFINER function is a one-line diff.
  - `COMMENT ON FUNCTION` when the function has a comment (none today).
  - **The body hash line binds the file to the approved document:** it is the same 16 hex digits Appendix C prints
    (model.ts's `bodySha256`, one helper for both), so the founder can tie each file to the line the approval hash
    covers. "Defined by" is migration-text.ts's `functionDefinedBy` (every migration that CREATE (OR REPLACE)s the
    name), so a migration that recreates a function with an unchanged body shows as a one-line header change, and the
    reviewer knows the recreation is a no-op. "Trigger function of" lists `table.trigger` from the catalog's triggers.
  - Each file ends with one newline. LF only.
- **`packages/db/functions/README.md`,** hand-written: what the files are, that they are generated and never edited,
  how to read a diff, and that they are not the approval of record (the document's hash is). The generator owns only
  `*.sql` in the directory; `--check` refuses any other entry but the README (a stray file, a directory, a symlink).

### 3.2 Generation and the drift check

- `generateDomainModel` returns, beside `text`, `functionFiles: ReadonlyMap<string, string>` (file name to content),
  built from the catalog read in the same snapshot as the document. `readCatalog` gains the definition, owner, ACL
  rows (grantee, grantable) and comment per function. The document's renderer ignores the new fields, so its text is
  unchanged (a test asserts the document is byte-identical with and without them).
- **CLI** (`pnpm db:domain-model`): `--out` also writes the directory (`--functions DIR` overrides
  `packages/db/functions`): it writes each changed file, removes each `*.sql` no function produces, and never follows
  a symlink or touches another entry. `--check` also compares the directory: it exits 1 listing every missing, extra
  and differing file, each with its first differing line, and the regenerate command. `--summary-since` names, beside
  each function whose row changed, the file whose diff shows it: `(diff: packages/db/functions/<name>.sql)`.
- **The provenance line's "uncommitted changes to its inputs"** excludes `packages/db/functions` (an output, not an
  input): pathspec `:(exclude)packages/db/functions`.
- **Drift, where it already runs:** `domain-model.db.test.ts` gains the case "packages/db/functions matches the
  functions of a fresh migrated database", so the `db` job fails a migration merged without regenerating them, and
  ci.yml's `domain model` job runs `--check`, which now checks them too. **No workflow change.**
- **Not collapsed on GitHub:** no `linguist-generated` attribute for the directory, so "Files changed" shows the diffs
  open. A test pins that `.gitattributes`, if present, does not mark them generated.

### 3.3 Who reads the diffs

- `.claude/skills/new-migration/SKILL.md`: regenerate with `--out` (it writes the files), commit them in the same PR,
  and report each changed function as its file's diff, not its migration block.
- `.claude/agents/security-reviewer.md`: on a migration, read `packages/db/functions/*.sql` diffs first: SECURITY
  DEFINER without a pinned search_path, a widened grant, a removed scope check, a changed `app.practice_ids` read.
- `docs/runbooks/github-governance.md` step 6 (the founder's approval): each function the summary lists links its file;
  "Files changed" shows exactly which lines of it changed.
- ADR 0068 records the decision; `docs/product/test-matrix.md` gains DBF-01 to DBF-05.

## 4. Tests: DBF-01 to DBF-05

- **DBF-01** (db): a fresh database migrated with every migration regenerates `packages/db/functions` exactly (no
  missing, extra or differing file); a stray file fails `--check`.
- **DBF-02** (db, the drift probe): a probe migration's function body changed by one line changes only that function's
  file, by that line and the body-hash line, and the hash equals the document's Appendix C row. A grant added, a
  SECURITY DEFINER flip and a `SET search_path` removed each change the file.
- **DBF-03** (unit): file naming: one file per name, overloads in one file in signature order, a name outside
  `^[a-z_][a-z0-9_]*$` or over 63 bytes refused, output deterministic for any input order (property test).
- **DBF-04** (unit + db): `--out` writes and removes stale `*.sql` only, leaves the README, refuses a symlink;
  `--check` exits 1 naming each file and its first differing line; the document's text and SHA-256 are the same with
  the function files as without.
- **DBF-05** (unit): ACL rendering (PUBLIC revoked or kept, grant option, sorted grantees, owner), comment rendering,
  "Defined by" and "Trigger function of" lines, and the summary's file pointer.

## 6. Rejected options

- **A diff tool over migrations** (find the previous definition by parsing SQL): reconstructs what the catalog already
  knows, misses ALTER FUNCTION and grants, and shows nothing in git history.
- **Bodies inside the domain model document:** changes the approved text and its hash, and makes a 7,000-line document
  longer; the audit's best option keeps the text unchanged.
- **One file per signature:** a changed argument list becomes a delete and an add, and a new overload renames nothing
  but scatters history; per name is clearer for review.
- **Marking the files linguist-generated:** GitHub would collapse exactly the diffs this exists to show.
