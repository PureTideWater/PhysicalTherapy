### False-refusal measurement (design check C.4; for the PR description)

Twin practice: 80,000 member IDs, 201,000 PCNs and 200,000 CCNs. Over set v2's 63 documents, refusals are **0 at floors 6/6/8 (as ruled), 0 at 6/6/6 and 0 at 6/6/10**.

Adversarial collision twins, built from set v2's own pages (documents refused out of 63):

| Class | Identifiers | With the stored-side rules | Without them |
|---|---|---|---|
| date: hyphenated dates as joined, stored as PCNs | 219 | 0 | 7 |
| word: letter-only words of 8 or more letters, stored as PCNs | 79 | 0 | 63 |
| tin: 9-digit member IDs equal to the set's TINs | 513 | 10 | 10 |
| zip4: 9-digit member IDs equal to the set's ZIP+4s | 500 | 10 | 10 |

The rules bring dates and words to zero. TIN and ZIP+4 collisions stay refused (fail closed) and are counted. On the ordinary twin, TIN and ZIP+4 collisions are 0, so the design does not need revisiting.

## Adaptations (where the build departs from the design, and why)

1. **Appendix A.3's JOIN regex** `^[ ]?[-‐-―]?[ ]?$` also joins two spaces with no dash. That contradicts section 5.3 ("two or more spaces ends the run"; a column gap). It is now `^(?:[  ]|[  ]?[-‐-―][  ]?)?$`. The test 'ZZ  1234567' fails under A.3's regex.
2. **The calendar-date rule** reads YYYYMMDD or MMDDYYYY, as 5.3 says, with years 1900-2099; the design gave no year range. DDMMYYYY is not dropped, so a stored 13012026 is still looked for. That is a gap the rule does not widen, and it is tested.
3. **The log codes** keep `screen_failed` apart from `screen_unavailable`. The design used MODEL_INPUT_SCREEN_UNAVAILABLE for both; the build logs MODEL_INPUT_SCREEN_FAILED for screen_failed, so an operator can tell the bound from a failure, and neither code carries content. screen_invalid is also logged (MODEL_INPUT_SCREEN_INVALID). Any non-InputRefusedError thrown by a screen is logged as MODEL_INPUT_SCREEN_FAILED, with its message never logged, and rethrown.
4. **Log messages are written as literals** in a switch, because lint:logs requires fixed text. The log carries `practice_id`, which is null on an evaluation call, kept as m15 says.
5. **issued.add is in one helper**, `issue()`, which freezes the check before adding it and is called by the two factories only. The lint test pins this. Improvement: an issued check is frozen, so its `practiceId` cannot be changed after it is issued; the design's object was mutable in-process.
6. **Extra construction checks** (improvements):
   - the cipher must be the practice's (`cipher.practiceId === practiceId`);
   - the practice must be in `authorizedBy.practiceIds` as well as in `access()`;
   - the request ID plus ':screen:'+UUID must fit the audit column's pattern;
   - the opened job scope's actor must be the service screen ID, as well as its practice.
7. **`syntheticRecordsCheck(identifiers)`** takes no floors argument (A.3 and 5.7 pass SCREEN_FLOORS). An issued check always uses the ruled floors and rules. Other floors exist only for the measurement, through `screenSet(…, rules)` and `pagesName`, which issue nothing.
8. **The 9-digit member IDs of the twin start with 9** (the never-issued SSN area); the CCNs start 77 and stay 13 digits. Values must be invented and never real-shaped, and this keeps the ordinary twin's TIN and ZIP+4 collisions deterministically zero. The design said only "9 digits".
9. **ContractPages and RequestInputs (new types):** the verifier, the eval set and requestFor/registerOutput take the document without the check. So `requestFor`, `registerOutput` and `verifyContractTerms` callers (the apps' db tests, e2e/models.ts, score.test) need no check. Only `proposeContractTerms` requires one.
10. **The two existing gateway.db contract tests** use a real check for north built on the app pool. MOD-12 is seeded through test-support/screen-world.ts rather than by loading the 835: the loader is apps/worker's, which model-gateway cannot import. The seeded values are MOD12_PRACTICE, the same constant the 835 is built from.
11. **#53 changed the m3 test.** That gateway.test test stubbed a contract screen ("no screen of its own yet"). It now runs the real screen and counts the connections it takes.
12. **MOD-12's practice has 5 claims.** The four extra ones have PCNs the screen leaves out: 97110 and 97530 (CPT codes), 20260101 (a date) and SCHEDULE (a word), with fixed member IDs SYNMBR120000xx. The fee-schedule twin writes every SCALE_THERAPY_CODES code, two synthetic NPIs, a 00- TIN, two ZIP+4s, a phone number and dates in every form.
13. **`recordContractScreenRequested` and `screenAuditRequestId`** were added (the design has the web write the event inline). This gives one place for the joined request ID.

## Adaptations (design -> today's code) and why
1. `screenRequestId` is not exported by the gateway; the web writes `${requestId}:screen:${screenId}` itself, the
   format patient-records.ts uses, and the db test asserts the event's request ID equals the reads', so drift fails a
   test. Proposal for the screen part: export a `screenRequestId(requestId, screenId)` and use it in both places.
2. The gateway logs `screen_failed` as MODEL_INPUT_SCREEN_FAILED (and screen_invalid as MODEL_INPUT_SCREEN_INVALID),
   not MODEL_INPUT_SCREEN_UNAVAILABLE as 5.6 wrote: better for operators (a failed read is not the bound). The web test
   asserts the split; the person sees one notice for both.
3. `requestFor` now takes `RequestInputs` (no check): the web test's `answer`/`pagesInput` and
   `apps/web/e2e/models.ts`'s `expectModelOutput`/`input` type changed from PurposeInputs to RequestInputs (three
   type-only lines in e2e/models.ts, outside my listed files but required for `tsc -p apps/web`; not one of #42's).
4. The check is built only when a gateway exists (`gatewayFor` non-null): with no model configured nothing is
   screened or audited.
5. Worker: the check is built at the practice's first readable document, not up front, so a practice whose examples
   are all unreadable is not read; still one per practice per run, never across practices or runs.
6. Allowlist (#53): `OUTSIDE_MODEL_PROBLEMS` already holds `refused:names_patient`, and `refused:screen_unavailable`,
   `refused:screen_failed`, `refused:screen_invalid` fall to `unmeasured`. The worker's `problemOf` already yields
   `refused:<code>` for InputRefusedError. So no change to packages/model-gateway/src/permitted.ts or eval/baseline.ts:
   names_patient is the example's own outcome (a rerun meets it again; counted, kept, no bar to record-permitted, as
   refused:document_kind), the screen not running is the run's setting (record-permitted refuses the run whole).
   eval/baseline.ts's synthetic-set rule (any `refused:` is an unmeasured case) is consistent: the synthetic set must
   show zero names_patient (the golden test), so one there blocks. Documented in permitted.ts's module comment.

## Adaptations from the design
- The design gives `useState(props.initialKind ?? (...))` with initialKind as an UploadKind. I built it as `initialKind?: string`, the kind's key, matching the design's own `initialKind="x12_835"`, and resolved it against the offered kinds. An unoffered key gives no kind (fail toward asking).
- The design wants the placeholder "first, disabled, selected". It renders only on a panel that started with no kind, so the Uploads page (835 preselected) shows no dead option. Once a kind is chosen, the placeholder cannot be chosen again because it is disabled.
- "The uploader limits the drop zone to the chosen kind's" types: the uploader already declared each file's type from the chosen kind (`declaredType(file, kind.contentTypes)`). `limits.contentTypes` only fed the no-kinds 835 default. The pages now pass the union, and the chosen kind still governs.
  - I did not add an `accept` attribute: 835s often carry .835 or .txt names with no MIME type, so `accept` would hide valid files.
- The refusal is tested through the extracted pure `batchProblems` plus static markup, because apps/web has no DOM test environment (no jsdom or testing-library). The browser path is covered by the e2e step.
- #53 changed none of these files, so there was nothing to adapt from #53.
