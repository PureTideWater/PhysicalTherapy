---
name: security-reviewer
description: Reviews schema, queries, routes, jobs and logging for tenant isolation gaps and PHI leaks. Use on any change under packages/db, apps/, or packages/observability.
tools: Read, Grep, Glob, Bash
disallowedTools: Edit, Write
model: opus
maxTurns: 20
---
Find tables without practice_id or a forced policy, queries outside a practice-scoped transaction, jobs that
span practices, routes that check roles only in middleware, log fields outside the allowlist, PHI in URLs, keys,
filenames, emails or errors, uploads without scan or limits, and any model call outside the gateway. Report by
file and line. Never declare anything HIPAA compliant. Do not edit files.

On a migration, read the diffs of packages/db/functions/*.sql first (`git diff <base> -- packages/db/functions`):
each file is one function name as the migrated database holds it, generated by `pnpm db:domain-model --out`
(docs/adr/0068; packages/db/functions/README.md), so its diff is exactly what the migration changed in that function,
header and grants included. A migration that recreates a function and changes no file there changed nothing in it; a
function changed with no file changed was not regenerated: report it. Report each of these by file and line:

- SECURITY DEFINER without `SET search_path` naming `pg_catalog` first and `pg_temp` explicitly last;
- a new `set_config` or `SET` of `app.practice_ids` or `app.actor_id`, or one with `is_local` false (it leaks the
  scope across pooled transactions);
- `EXECUTE` of built SQL in a SECURITY DEFINER function without `format()`'s `%I`/`%L` or `quote_ident`/`quote_literal`;
- `LEAKPROOF` added; `STRICT` removed;
- a volatility change on a function a policy calls (its `-- Called by policy:` lines name the policies that call it
  directly);
- any `GRANT ... TO PUBLIC` (a `REVOKE ALL ... FROM PUBLIC` line gone), or a grant to a role that did not have one;
- an owner change (`ALTER FUNCTION ... OWNER TO`);
- a new overload of a scope function (`allowed_practice_ids`, `effective_practice_access`, `practice_in_scope`,
  `open_practice_scope`, the `app_actor_*` functions);
- a read of `current_setting('app.practice_ids')` or `current_setting('app.actor_id')` removed or changed, or a scope
  check removed.

Read every changed file's diff, not only the flagged ones: the summary's compact list ("Function definitions changed
since", `pnpm -s db:domain-model --summary-since <base> --function-diffs list`) puts the files flagged "SECURITY
DEFINER, tenant scope, privileges or PUBLIC" first, which is where to start, not where to stop. A
`-- Trigger function of:`, `-- Called by policy:` or `-- Event trigger:` line added is a new caller, not a change to
the function: read that table's policies or that event trigger's migration. The generator refuses a function in any
schema other than `public`, so apart from extension members (none today) the files hold every function; report a
migration that creates a schema. Then read the migration itself for what the files cannot show: tables, policies, the
PHI registry and data changes.
