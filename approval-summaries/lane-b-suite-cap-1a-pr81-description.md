## What changes

SUITE-CAP-1a, bounded reads (part 1a of `designs/suite-cap-1-triage-locks.md` on `claude/build-ops`). Triage and the audit report read a month's lines in batches, the report streams, and the quadratic stage write goes. - **Triage's stage write** (`advanceStages`, D12): each wanted line's latest stage is read with a `LEFT JOIN LATERAL` lookup on `line_status_by_line`, whatever the planner's statistics say about the transaction's own rows.
- **Triage's candidates** (`judgedCandidates`, D13): read through a cursor 2,000 at a time, each batch audited (one event per row, as before) and judged while its traces are in hand, then dropped; one release loader serves every batch. Triage and the workbench's waiting patterns (opening a case, the Cases page) use it. `candidateRows` and `candidateLines` stay.
- **The audit report** (D14, D17, D18): its lines read through a cursor 2,000 at a time; per batch the deadlines, today's mapping to a line, the running figures and the CSV row. Each CSV row is kept in an off-heap byte arena (`apps/worker/src/report/csv-arena.ts`) with a small sort index, and streamed in the report's order after the last batch. The CSV is written and the arena released before Chromium prints the PDF. The patient-balance check folds over claim-ordered batches of 2,000 case lines, and the practice's ledger entries are read once per report.
- **`lineShares`** (D16): the adjustments are grouped once, by claim and by line, in their query order.
- **The review round:** the patient-balance batches share one read of the practice's match history (its match order, matches, and matched claims' lines and reversals: `practiceChains`), and each batch reads only its own claims (`chainContextFor`); `chainContext`'s other callers send the same queries as before. The CSV arena is released on any failure after it is made. Batch sizes and the arena's chunk are options for tests (`TriageOptions.batches`, `ReportOptions.batches`).

Decisions taken during the build (recommended option, with reasons):
- **Pattern order.** Today's patterns tie on payer, plan, behavior and rate record when they differ only in mapping kind or contract version, and a tie keeps the order of its first line in the report. The fold keeps each pattern's first line's sort key and breaks ties by it, so the content is identical.
- **The patient-balance batches are claim-ordered.** The fresh-head probe found unordered batches of case lines each spanning about 1,900 claims, so `claimLines` read 2.6 times the base's rows (a projected 28 minutes, past the job's 15-minute attempt). Ordered by claim, each claim is read once across the batches (34 calls, 100,072 rows, against the base's 100,000).
- **The match history is read once per report** (the review round). The money reviewer noted, and the code confirmed, that each patient-balance batch's `lineCorrections` re-read the practice's whole match history and its matched claims' lines (`claimLines`, slow until 1b's index): once per batch instead of once per report, for any practice with a reconcile history. Now one shared read; three new tests failed on the code before it (query counts of 5 and 3 where 1 is expected).
- **A failed print leaves the sealed CSV stored.** The CSV is now written before Chromium prints (design 5.3 point 4), so a print failure leaves a sealed CSV under that attempt's own key that no row names. The application role cannot delete objects (`infra/lib/constructs/application-role.ts`, asserted by `application-role.test.ts`), and adding that grant would weaken a security invariant, so it is recorded instead (ADR 0083, As built): the same class as the base's orphan PDF after a failed CSV write, sealed with the practice's data key and unreadable once the key is destroyed (docs/adr/0018).
- **CAS-41.2 measures at 10,000 and 20,000 lines, not the design's 2,000 and 10,000.** Below about 3,830 lines the candidate batches, and below about 9,710 the case-line batches, are not full, so the 2,000-line point understates the batched readers' constant and the per-line slope fails for that alone. ADR 0083 records it.
